# Native RADE waveform meter items

JJ approved the FreeDV-like instruments and then clarified that every RADE meter should behave like an ordinary meter, usable in Stack or Canvas and mixed with existing items. On 2026-10-11 JJ approved the revised design. This implements the first selected instruments: microphone and decoded speech waveforms. The broader receive status, SNR, spectrum and station-list instruments remain later increments under the same composition and high-resolution contract.

## User behavior

Two non-singleton catalog entries, `meter.radeMicWaveform` (Microphone waveform) and `meter.radeSpeechWaveform` (Decoded speech waveform), use the normal add, source/session binding, properties, visibility, duplication, sizing and persistence workflows. Stack and modern Canvas (`ContentLayout::FreeCanvas`) reuse existing layout projections. The container owns its chrome; the item has a trace title, axes and source/status caption. A RADE layout is an editable arrangement, not a special host.

Each item defaults to five seconds of history, fixed normalized amplitude -1 to +1, amplitude ticks every .2 and time divisions every second. Properties select 5000, 1000 or 100 milliseconds. No hidden averaging, smoothing, autoscale, scalar meter dynamics or peak-hold reduction. Retain full-rate samples, draw actual samples at close zoom, and preserve positive/negative extrema per physical display column at wide zoom. Respect the actual pixel density. Missing intervals break paths; real zero PCM is valid silence.

The mic item has `SourceStage` = Conditioned or RawMic. **Conditioned is the default**, preserving the approved encoder-input interpretation. RawMic is an additional explicit option for microphone setup before the RADE TX path has been used. Labels identify the actual tap: conditioned encoder input at 16 kHz, raw microphone at 48 kHz, or decoded speech at 24 kHz. Selecting a meter must not key, connect, demand/open a microphone, activate a restored decoder, alter TX path selection or run a second conditioner. Conditioned data is unavailable before the existing MOX-latched RADE path starts; the face explains that and the RawMic option. No unlabeled fallback between taps.

The microphone is a physical TX source, not an independent microphone for every RX slice. Its source binding must match `RadioModel::txBoundSlice()`; other bindings show an explanation rather than another slice's samples. Decoder speech belongs to the exact live RADE channel/receive source. Mode, sideband, connection, RX route or physical source replacement must retire its generation and clear stale history. Ordinary no-data intervals age out on the live five-second timeline and remain blank, with an explicit waiting/gated/source state. This timeline is observation time; it does not establish microphone-to-decoder latency alignment.

## Observation architecture

Preserve all current signal routing, codec, DSP parameters and threads. Add observational copies only. Raw mic taps after source override at TxWorkerThread.cpp:734 (RADE path) or :1002 (ordinary WDSP path), mutually exclusive and before processing. Conditioned mic taps the actual int16 block at :850-860 outside the keyed codec emission. Decoder taps one mono leg of the actual float stereo output at RadeChannel.cpp:824-827, before accumulation/pacing/zero padding. Existing rxSpeechReady is unsuitable because it includes playback padding. Native raw WDSP doubles may convert to float32 for this display; PCM16 uses division by 32768.0f, preserving every integer sample. Never modify the buffers sent to DSP, codec or playback.

Three stream kinds: RawMicrophone, ConditionedMicrophone, DecodedSpeech. Use a core-only Qt queued publisher per physical stream with a single producer, one in-flight immutable batch, preallocated leased packet storage and bounded producer-owned pending PCM history. All PCM crosses the thread boundary in a queued signal; an atomic acknowledgement/control token may release a batch after the main consumer copies it. Acknowledgement alone does not permit mutation while another shared lease exists. No new mutex, blocking wait, producer-consumer queue eviction, per-sample signal or new thread. Qt event allocation is limited to batch publication, maximum once per 33 ms per stream. Disabled streams do no sample copying or min/max work. Pending storage retains at most five seconds at the stream rate and at most 4096 native-block segment records. Each published batch contains at most the latest 100 milliseconds of samples; older backlog is discarded with explicit dropped-frame/sequence gaps so UI recovery cannot cause a five-second copy on the audio thread. Rate/kind and incoming block bounds are validated before allocation or processing. Overflow discards only observer history and records sequence/time gaps. Packet storage and model memory cannot grow with past PTT/mode changes.

A GUI-neutral model owns subscriptions, physical stream generation tokens and one main-thread history/cache. Multiple visible views of one source share capture and immutable snapshots; they do not each attach to the audio ring. Aggregate demand by window owner plus slice/stream. Source changes publish a coherent opaque token at block entry; compare before publication and reject retired tokens on receipt. Capture invalidation cannot reset conditioner/codec state. Source underflow and padded missing input are not measured silence. TCI's early-return path is explicitly unavailable initially, not relabeled modem data. A decoder with no actual output emits no fake PCM. Observation overflow and unavailable status never alter audio counters or routing.

Per-window MeterPoller adds a separate 33-ms waveform refresh path while typed visible targets/previews exist, leaving scalar refresh and DSP reads unchanged. ContainerSourceAdapter resolves source/session and rejects foreign/stale sources before model queries. Preview faces read the same cached snapshots without another physical subscription. New faces have no scalar reading bindings, MMIO selectors or MeterDynamics processing. Persist visual configuration and existing geometry/context only; PCM, tokens, timestamps and source state are runtime data. No container document schema bump.

## First-phase boundaries and decisions

The deliverable includes local desktop observation and remote Core desktop observation, following JJ's explicit scope answer. Remote instances use a negotiated, bounded exact-PCM observer feed from a capable Core. Older Cores without that feed show Unsupported. They cannot substitute mixed/Opus program audio or local DSP. The settled transport contract follows the existing authenticated Core media path and is documented in Waveform media v1 below. No phone waveform UI, waveform file export, automatic capture trigger, speech conditioning policy change, microphone permission change or radio test is included.

This touches the core RX path with an observer at decoder output, so it requires tests for unchanged audio bytes/cadence, co-hosted slices and safe retirement. New code is Nereus-original; FreeDV supplies verified plot/tap facts, not code. FreeDV references: freedv-gui a8d8424 main.cpp:1377-1382, defines.h:54-56, TxRxThread.cpp:266-278,443-457. Native recon and exact lifecycle sites are in work/waveform-audio-recon.md and work/waveform-meter-recon.md. Preserve all existing source headers/inline comments; read HOW-TO-PORT before any actual port.

## Acceptance

- Both entries instantiate through the actual registry and work mixed with normal meters in Stack and FreeCanvas.
- SourceStage/window/config, source/session, visibility, order, duplication and geometry survive actual document/workspace round trips; invalid config cannot partially mutate state, and opaque fields survive no-op Apply.
- Full-rate raw 48k, conditioned 16k and actual decoded 24k observation retains sample identity and extrema; capture/pending memory and queued notifications remain bounded when GUI stalls or leases are retained.
- Default conditioned semantics, raw setup option and missing/gated/unsupported state are accurate. No source change, retired channel or foreign session can replay old PCM.
- The plots preserve impulses at physical column boundaries, including the final sample, at DPR 1/2 and all three windows; gaps are not connected and static axes stay fixed.
- Producer observation cannot change codec/EOO/modem/audio bytes or ordering, and disabled/full observer buffers cannot block audio or the other slices. No R1 include violations.
- Visible duplicates share one capture/cache; hiding one preserves the other, hiding all disables capture, and preview does not create another live consumer.
- Selected tests are built before execution; settings sandbox/fakes only. NereusSDR and nereusd build; CPU and native QRhi output are inspected without connecting/keying or normal first launch.

## Remote Core scope update — JJ, 2026-10-11

JJ answered the pending scope question: “Include remote Core desktop support now.” This supersedes the earlier local-first assumption wherever it appears above. The current deliverable includes exact microphone and decoder waveform samples on a desktop connected to a capable Core. Older Cores without the negotiated observer feed must report Unsupported explicitly. The additional feed remains observational, visibility-demand driven and bounded; it must preserve full-rate samples, source generations and gaps, and cannot use Opus/program audio as a substitute. The transport extension follows the existing Core media/control code; its settled contract and verification are recorded below.


The settled remote extension uses the existing authenticated media path and a dedicated optional waveform channel, rather than control-session JSON audio. It sends incremental exact float32 PCM with explicit kinds, native rates, sequence/time spans, physical-source generation and delivery generation. The existing model remains the only publisher consumer/ack owner; session senders copy at most100ms and cannot hold producer leases. Known authorized slice subscriptions are visible-demand driven; decoded speech follows hearing permission, microphone follows its actual remote writer or the existing station transmit holder. Full-rate bandwidth is reserved through the current budget/pacer, with explicit refusal rather than hidden decimation. Older Core negotiation stays compatible.

Remote microphone validity is an observer-only addition to the existing pull API: buffer startup, silence insertion, underflow fade, failed reads, Shed and use-change races create gaps. Physical writer and line/session generations retire old data. Core time is mapped by the existing clock-probe estimator; no audio playout delay or packet-arrival substitution is applied. The remote model stores Core-time history and translates immutable snapshots so later offset corrections do not manufacture gaps. New protocol details and the deliberate optional-feature minor11 policy are recorded in the remote media contract by the transport implementer.

Remote wire contract: [Waveform media v1](2026-10-11-waveform-media-v1.md). This is the Nereus-original protocol extension for the authorized remote desktop scope.


Remote lifecycle ruling: `RadioModel::radeWaveformModel()` returns a stable model after initial creation; ordinary reads do not synchronize/emit source changes reentrantly. Existing source lifecycle hooks remain, and one33ms main-thread model timer requests observational endpoint refresh while capture demand or authenticated visible refresh-only demand exists. Refresh-only demand is independent of publisher capture, so conditioned input becoming available on a headless Core is noticed even before a stream is admitted. Hidden/unauthorized/session-retired demand clears both; a budget-refused stream leaves its publisher disabled. This adds no DSP thread, mic demand, routing, or processing change.


Source retirement refinement: the TX worker increments an atomic observation-source epoch when the actual selected category changes, retaining A→B→A changes between GUI refreshes without adding producer events or PCM metadata. Physical TX identity also includes the existing PC capture generation/device/config revision and remote writer/line/use generations. A queued microphone batch requests main-thread source synchronization before token validation, with receiver/publisher lifetime guards; retired batches acknowledge without entering the new history. Decoder observation and DSP bytes remain unchanged.

Clock-origin correction: the existing audio receiver clock is elapsed process time, while waveformNowNs and the Core default echo clock use absolute steady-clock coordinates. The GUI bridge converts the estimator offset using the audio-local versus waveform-local origin delta, with checked arithmetic. The model receives Core-minus-waveform-local offset; actual waveform timestamps remain unchanged. This does not alter the audio estimator, its clock, or playback delay.

Packet lease contract: pooled `WaveformBatchPtr` data remains immutable for the lifetime of every owning strong lease. Internal consumers copy the batch or retain that lease while reading. They must not use a raw pointer, reference, or resurrectable weak reference after releasing the owning lease, because the fixed pool can then reuse the payload. GUI `WaveformSnapshotPtr` values are independent immutable snapshots. Review found no weak-lease consumer in the implemented paths.

Receive identity refinement: decoded observer generations include decoder-route installation, slice stream index/epoch and receive-worker replacement. Main-thread source synchronization runs before accepting queued observation packets so a stream migration cannot reintroduce retired speech history. This changes observation identity only; receive processing and routing keep their existing behavior.
