## Source facts and diagnosis

Thetis was inspected at `v2.10.3.15`. Its `console.cs:24281–24310` selects receiver pixels while DUP is enabled, and `display.cs:5014` gates measurement on MOX, two-tone testing, Show Two-tone Measurements and DUP. The legacy matcher and six-peak calculations are sourced from `display.cs:5014, 5223, 5518–5590, 5600–5718, 6713–6738`; feedback classification is sourced from `PSForm.cs:1123–1138`; and AmpView series construction from `AmpView.cs:107–153, 156–257, 355–482`, all at the same pin. Existing `AmpViewChart` and call sites establish magnitude `[0,1]`, gain `[0,2]`, phase `[-180,+180]`, zoom `[-45,+45]`, and Low Res paint stride 4 versus 1. The cited Thetis source and numerical behavior remain the basis for the ported detector and applet feedback thresholds; Thetis notices, tags and provenance are retained in their source files and attribution tables.

The display source determines what a reading means. With DUP on, local spectrum input is the ordinary receiver display plane and remote input is an accepted receiver trace. The UI labels that input **Receiver spectrum**; this label does not certify a coupler, PA output, or dedicated PureSignal feedback DDC. With DUP off, the existing TX display path uses the digital siphon before correction and the PA (`third_party/wdsp/src/TXA.c:580–584`); those pixels are ineligible as measured RF IMD. Ordinary receiver suspension or absent frames must produce waiting/blank current readings rather than a new source route. No protocol or board fact was inferred from SmartSDR or a synthetic fixture.

The first confirmed defect was double cropping. `updateSpectrumLinear` already cropped full FFT bins and reduced them into the visible `m_renderedPixels`; `drawImdOverlay` then applied `visibleBinRange` a second time. At a 192 kHz sample rate, 48 kHz visible span and 800 visible samples, the second crop retained only indices 300–500. A six-peak visible fixture at 100/220/340/460/580/700 lost the products needed for a valid readout. The renderer now detects against the entire visible array and maps markers from those same coordinates. The 10 dB trigger, matcher geometry, numerical formulas and source smoothing constant remain unchanged.

The source-order audit found a separate AmpView lookup issue. Vendored WDSP (TAPR pin `b02d5bac`) `third_party/wdsp/src/calcc.c:448–475, 505–529, 1263–1295, 1791–1796` writes measured values into sixteen envelope buckets in bucket-major physical-slot order. The published measured X values are therefore not guaranteed monotonic; `Ps3DisplayAdapter` preserves that order. AmpView now keeps the displayed order and builds a sorted GUI-only lookup copy. It does not sort or alter DSP samples, average duplicate X values, or synthesize correction domains. Ambiguous duplicate neighborhoods and measured-phase branch-cut interpolation return blank values.

## Implemented behavior

Tasks 1–3 corrected gate ownership and produced a cached measurement frame. `MoxDisplayController` mirrors the current local/remote facade testing and Show gates to panes while the committed keyed TX pan remains the owner; focus does not select the measurement source. The saved Show preference wins over the unpersisted legacy coordinator mirror when the key exists. A new or rebound panel receives current state, and gate-off dirties the native overlay so stale GPU markers clear while MOX remains on.

The GUI presenter accepts one finalized spectrum plane per new source identity. It preserves the TNF-dented display-plane semantics and does not find peaks or advance EMA during paint, hover, tab changes, exposure, or GPU refresh. Invalid gates, ineligible source, missing/stale frames, missing products and out-of-view products clear current aggregate values. Independently matched products can remain visible when other products are absent; full summaries require all six. Recovery starts a new smoothing interval. Individual products retain the stronger-fundamental relative reference; worst-order summaries retain the weaker fundamental against the stronger product. Existing OIP formulas are unchanged.

The IMD rail and optional same-pan inspector share that cached frame. They expose source/status, named shaped markers, absolute and relative levels, RF frequency, explicit unequal-tone references and blank invalid values. Product selection, guide visibility, inspector state, tab changes and window opening have no TX, DUP, FFT-parameter or radio-settings action. The per-pan keys are `PureSignalImdInspectorVisible` and `PureSignalImdGuidesVisible`; they use existing `AppSettings` persistence.

The applet and Bench use the existing `PureSignalSessionFacade` actions, permissions, arming refusals and settings synchronization. Calibration feedback, correction-applied state, native engine stage, calibration counts and correction counts remain distinct. The full window retains supported calibration/file controls, raw diagnostics, hardware peak reference and cached IMD frame. AmpView keeps the existing facade snapshot → `Ps3DisplayAdapter` → plot-data feed, freshness, generations, sequence rejection and current/retained distinction. It now displays linked magnitude/gain and phase plots with a shared input cursor and independent data domains; cursor and series visibility are session-local.

Waterfall correction annotations are GUI metadata attached to accepted retained row sequences. Synthetic, repeated, blended, stale and pre-edge queued rows cannot consume an edge. Retune, reconnect, clear, expiry, wrap, pause and rewind preserve or invalidate row identity according to the existing history lifecycle. Frequency guides use the same viewport mapping as the spectrum. Hiding guides leaves correction history visible. No Core history format or remote transport changed.

The final integrated GUI repair adds a **Nereus-only presentation freshness policy**: a current eligible frame expires after `max(1000 ms, five expected frame intervals)`. The interval uses the remote target FPS when available, otherwise the local display timer interval. This is not an OpenHPSDR protocol timeout, WDSP/DSP parameter, or maintainer-selected radio default. It prevents stale values and markers from appearing current while retaining the held trace and waterfall history. An explicit remote `NeedKeyframe` transition invalidates immediately; local input with no arrival callback is bounded by the GUI display timer. During remote keyframe wait, already queued decoded Frames remain in playout order and continue to render their held trace and waterfall rows, but `measurementCurrent=false` prevents IMD acceptance, EMA updates, signal emission, and current-state revival. Only Frames accepted after the recovery keyframe are measurement-current. A new eligible frame restores Valid state and reseeds EMA. Tests pin the 1,000 ms boundary, +1 ms expiry, one-shot invalidation, 2 FPS → 2,500 ms, recovery reseed, and disabled-gate preservation.

Correction events now capture the current GUI accepted-frame ordinal and IMD context when the correction predicate changes. Only an eligible receiver row accepted after that edge and in the same context may consume it. The ordinal is GUI-local and independent of the transport encoder sequence, so a queued pre-edge row or encoder wrap cannot backdate the marker. Several edges observed before a suitable row coalesce to the latest state; the GUI has no RF-clock timestamp for assigning intermediate transitions.
