NereusSDR uses libdatachannel for direct ICE, DTLS, SCTP, and SRTP media
transport. The pinned source is fetched from:

  https://github.com/paullouisageneau/libdatachannel/tree/v0.24.5

The complete license is supplied in MPLv2.txt. Corresponding source for the

through the source URL and NereusSDR's written source offer.

Modification (MPL-2.0 section 3.1): the desktop/Core build compiles the
covered file src/peerconnection.cpp with a change of its own. PeerConnection::
setRemoteDescription() keeps the remote description (and with it the
fingerprint the DTLS handshake is checked against) before it gives the ICE
agent the description, instead of after, so a handshake that completes at
once cannot be checked against no fingerprint. The change is the source
file cmake/patches/libdatachannel-keep-remote-description-first.cpp in the
NereusSDR source, which cmake/NereusRemoteMedia.cmake puts in place of the
two lines it reorders in a copy of peerconnection.cpp in the build tree
(nereus_patch_libdatachannel_remote_description_first). Because it becomes
part of a covered file, the change is licensed under the Mozilla Public
License 2.0, like the rest of peerconnection.cpp, and carries that file's
MPL-2.0 notice at the top; it is not under NereusSDR's GPLv3. Its source is
offered with NereusSDR's (SOURCE-OFFER.txt).

Modification (MPL-2.0 section 3.1): NereusSDR applies
cmake/patches/libdatachannel-0003-retain-juice-agent-through-turn-release.patch
to src/impl/icetransport.cpp. A scheduled retirement owner keeps a closing
libjuice agent and its initialization token alive until its bounded TURN
release and resolver work finish, rather than waiting in shared transport
teardown or destroying the agent while that work still owns it.

Modification (MPL-2.0 section 3.1): NereusSDR applies
cmake/patches/libdatachannel-0004-retain-ice-lifetime-anchor.patch after that
retirement change. It changes include/rtc/configuration.hpp,
src/impl/icetransport.hpp and src/impl/icetransport.cpp to retain an optional
application ICE resource until the retiring agent destroys its socket.
The agent is released before that resource and its initialization token.

Modification (MPL-2.0 section 3.1): NereusSDR applies
cmake/patches/libdatachannel-0005-defer-dtls-startup.patch to
src/impl/peerconnection.cpp. When ICE connects, DTLS initialization is
queued on the peer connection's existing processor instead of starting
inside libjuice's Connected callback, which holds the ICE registry lock;
starting it there could wait on the SSL mutex while a receive worker held
that mutex and sent a relayed handshake record through the registry.

Modification (MPL-2.0 section 3.1): NereusSDR applies
cmake/patches/libdatachannel-0006-recheck-pool-queue-while-idle.patch to
src/impl/threadpool.cpp. An idle worker of the library's thread pool waits
at most 100 ms before it looks at the task queue again, rather than
waiting with no time limit for a notification, so a queued task is still
taken when its wake-up reaches no worker.

Modification (MPL-2.0 section 3.1): in Windows (MinGW) builds, NereusSDR
applies
cmake/patches/libdatachannel-0007-lock-shared-mutexes-once-when-made.patch
to src/impl/datachannel.cpp, src/impl/peerconnection.cpp,
src/impl/sctptransport.cpp and src/impl/track.cpp. Each of the library's
shared mutexes is locked and unlocked once in its owner's constructor, so
that on Windows (MinGW-w64) two threads never take its first lock at the
same moment, when one of them would run without the lock.

The five numbered patches are applied by cmake/NereusRemoteMedia.cmake to
build-owned copies of the pinned source. Their changes are licensed under
MPL-2.0, like the covered files they modify; those files retain their
upstream notices. The exact patches are supplied with NereusSDR's source
and its written source offer (SOURCE-OFFER.txt).

Modification (MPL-2.0 section 3.1): NereusSDR also compiles
src/impl/dtlstransport.cpp with a change of its own. The OpenSSL
DtlsTransport::start() sets the DTLS MTU before it registers for incoming
records, instead of after, so a peer's ClientHello arriving at once is
never handled with no MTU set (which failed the handshake). The change is
the source file cmake/patches/libdatachannel-set-dtls-mtu-before-incoming.cpp
in the NereusSDR source, which cmake/NereusRemoteMedia.cmake puts in place
of the first lines of that function in a copy of dtlstransport.cpp in the
build tree (nereus_patch_libdatachannel_dtls_mtu_first). Because it becomes
part of a covered file, the change is licensed under the Mozilla Public
License 2.0, like the rest of dtlstransport.cpp, and carries that file's
MPL-2.0 notice at the top; it is not under NereusSDR's GPLv3. Its source is
offered with NereusSDR's (SOURCE-OFFER.txt).

The NereusSDR for iPhone and iPad app builds the same v0.24.5 source with
six patches: the Mbed TLS DTLS fingerprint check; C API deferred gathering
and peer-fingerprint access; bounded libjuice agent retirement; retained
candidate resources through actual ICE destruction; the deferred DTLS
startup; and the idle thread pool recheck, both described above. These
modify src/impl/dtlstransport.cpp, src/impl/icetransport.cpp,
src/impl/icetransport.hpp, src/impl/peerconnection.cpp,
src/impl/threadpool.cpp, src/capi.cpp, include/rtc/rtc.h and
include/rtc/configuration.hpp. The patches and modified files remain
MPL-2.0 and are published with NereusSDR's source under
ios/patches/libdatachannel/ and ios/NereusKit/Sources/CDataChannel/.
